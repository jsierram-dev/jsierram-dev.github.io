Mockups: tarjetas de proyecto pensadas para un reclutador

Un reclutador mira un portfolio ~7 segundos de media. Hoy el texto de cada proyecto (campo "role") es un párrafo largo explicando arquitectura de 5 repos — perfecto para una entrevista técnica, pésimo para un primer vistazo. Las 3 propuestas de abajo resuelven lo mismo con menos texto: objetivo en 1 línea, por qué cada tecnología (no solo el nombre), y enlaces directos a cada repo cuando el proyecto usa varios (similart usa 5, CalisMap usa 3). Todo el detalle técnico actual se puede mantener, pero colapsado/secundario — para quien sí quiere profundizar (otro dev, o el mismo reclutador en una segunda pasada).

Propuesta A

Grid de tarjetas escaneables (evolución directa del diseño actual)

Misma tarjeta de hoy, pero el párrafo largo se reemplaza por 1 frase de objetivo, los chips de tech llevan un tooltip con el "por qué" al pasar el mouse, y se agrega una fila de pastillas de repos (clicables, con 🔒 si el repo es privado). El resultado/outcome queda como una línea destacada.

Propuesta C

Lista estilo "CV": 1 frase + detalle colapsado

La más agresiva en recorte: cada proyecto es una línea con una frase en negrita (el resultado, no el proceso), iconos de stack, y pastillas de repo. El párrafo técnico de hoy no se pierde — vive en un <details> plegado por defecto, para quien quiera seguir leyendo.

Ver arquitectura y rol técnico completo

Diseñado y construido en solitario, repartido en 5 repos. similart-gateway enruta login a jp-back-auth y partidas (HTTP+WS) a similart-back-room. jp-back-auth emite JWT RS256 validados localmente por cada backend. jp-similart-api comparte los tipos entre frontend/backend.
